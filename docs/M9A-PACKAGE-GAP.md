# M9a gap: the package does not know `head_split` / `belly_open`

V3's M9a (wire the PR #35 cut types into the Frankendom finishers) is blocked on the package, not on V3. Receipts at physics main 0fc0fcb (the V3 pin c0b55ad is an ancestor):

- `rd.row.severable` is generated by `src/generate.mjs` from `data/ragdoll-role-table.json` `severable.units`: exactly six units (head, arm_left, arm_right, leg_left, leg_right, torso_waist).
- `createCutRig` (`src/three-cuts.mjs` lines 17, 27, 33) builds `units` from `rd.row.severable` and throws for a cap or region naming an unknown unit. The PR #35 manifest has `cap_belly_opening` with `shown_when_cut: "belly_open"` and `cap_split_head_*` with `shown_when_cut: "head_split"`, so loading the new GLB + manifest throws at creation, for every body, with no finisher involved.
- `rd.cut(unit)` (`src/engine.mjs`, `cut`) throws `unknown severable unit`, and a unit is defined by a `cut_role`: the joint of that role is removed from the capsule chain. Neither new unit fits that shape:
  - `belly_open` detaches nothing. It has no joint to remove.
  - `head_split` needs the two halves to move independently, but the ragdoll has ONE `head` capsule and no per-half roles.

V3 cannot fix this without hacking around the package (patching the generated row, or faking the units in the manifest), which the contract forbids.

## What the package must add

1. **Units in the role table** (`data/ragdoll-role-table.json` `severable.units`), generated into the row as today:
   - `belly_open`: `cut_role: null`, `carries_roles: []`, `gear_slots: []`, `detaches: false`. `rd.cut("belly_open")` adds the id to `rd.cuts` (so `createCutRig` shows the cap) and removes no joint, returns `{ unit, mass_kg: 0, carries_roles: [], gear_slots: [], cap: null, props: [] }`. Allowed on a body that is already cut at the waist or not (it sits on the upper torso piece); allowed once.
   - `head_split`: a unit that requires `head` not necessarily cut. See 2.
2. **Two head half roles** for independent halves. Add roles `headLeft` and `headRight` (parent `head`, the head's mass split 50/50, capsules sized to half the head, fixed joints) in the role table. Until `head_split` is cut, the pair is welded to `head` (fixed constraints) and the pose is unchanged (the role count grows by two; `generate` and the calibration table must be re-run and the golden for the ragdoll row re-pinned with the reason). `rd.cut("head_split")` removes the `headRight` weld (or both welds with opposite impulses) so the halves separate; `copts.impulse` applies to the right half, and an optional `copts.impulseLeft` to the left. If `head` is cut first the halves ride the head; if `head_split` is cut first the head's own cut still takes both. `carries_roles` for `head` becomes `["head", "headLeft", "headRight"]`.
3. **The skin mapping**: `src/three-rig.mjs` must drive the bones the new manifest uses for the halves (both halves are bound to the same Head-side bones as the head, so with no change to the bones the halves cannot diverge). Either the halves' bones follow `headLeft` / `headRight` when `head_split` is cut, or the package exposes the half capsule poses so V3 can drive two Head bone copies. This is the one design decision for the physics repo to take; the minimum is to expose `partIds` for the halves in `readPose()`.
4. **Docs and tests**: `docs/API.md` (the six-unit sentence), `docs/CUT-CONTRACT.md` (the "What V3 must do" paragraph), `data/rules.json` only if a zone should map to the new units (it should not: they are finisher-only, never chosen by a zone hit). Tests: units list, `cut("belly_open")` leaves `rd.cuts` with the id and the constraint count unchanged, `cut("head_split")` leaves two bodies that separate under an impulse, `createCutRig` accepts the PR #35 Minotaur manifest.
